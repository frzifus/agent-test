# Issue #13: Add a TypeScript Library

## Problem

The current codebase is a Go-only library with math functions (Add, Sub, Mul, Div, IsOdd, IsEven). The task is to add a TypeScript library that provides equivalent functionality, allowing JavaScript/TypeScript developers to use the same math operations.

## Current State

- The repository contains a Go module (`go.mod`) with package `agent_test`
- `math.go` contains the following functions:
  - `Add(a, b int) int` — addition
  - `Sub(a, b int) int` — subtraction (TODO, returns 0)
  - `Mul(a, b int) int` — multiplication (TODO, returns 0)
  - `Div(a, b int) (int, error)` — division (TODO, returns 0, nil)
  - `IsOdd(n int) bool` — checks if number is odd
  - `IsEven(n int) bool` — checks if number is even
- `math_test.go` contains comprehensive tests for Add, IsOdd, and IsEven functions
- No TypeScript or JavaScript files exist in the repository
- No `package.json` or TypeScript configuration exists

## Proposed Changes

   - Package name: `@frzifus/agent-test` or `agent-test`
   - Version: `1.0.0`

   - `sub(a: number, b: number): number`
   - `mul(a: number, b: number): number`
   - `div(a: number, b: number): number` (throw error on division by zero)
   - `isOdd(n: number): boolean`
   - `isEven(n: number): boolean`

5. **src/math.test.ts** — Jest test file with equivalent test cases to Go tests

6. **.gitignore** — Add Node.js specific ignores:

### Function Signatures

```typescript
export function add(a: number, b: number): number;
export function sub(a: number, b: number): number;
export function mul(a: number, b: number): number;
export function div(a: number, b: number): number; // throws Error if b === 0
export function isOdd(n: number): boolean;
export function isEven(n: number): boolean;
```

### Implementation Notes

- TypeScript numbers are IEEE 754 double-precision floating-point (like JavaScript)
- Integer overflow behavior differs from Go — document this limitation
- Division by zero in JavaScript returns `Infinity`, but we should throw an error for consistency with Go's error handling
- Use strict TypeScript configuration for type safety
- Export all functions from `src/index.ts` for clean public API

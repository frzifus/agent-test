# GitHub Actions Workflow for Running Unit Tests

## Problem

The repository has unit tests (`math_test.go`) but no CI/CD pipeline to automatically run them on pull requests or the main branch. This makes it difficult to catch regressions and ensure code quality before merging changes.

## Current State

- **Project Type**: Go module (go 1.26.2)
- **Module Name**: `giithub.com/frzifus/agent-test`
- **Test File**: `math_test.go` - Contains tests for `Add`, `IsOdd`, and `IsEven` functions
- **Source File**: `math.go` - Contains `Add`, `Sub`, `Mul`, `Div`, `IsOdd`, `IsEven` functions
- **No CI/CD**: No `.github/workflows` directory exists
- **Tests can be run with**: `go test ./...` or `go test -v ./...`

## Proposed Changes

### New Files to Create

1. **`.github/workflows/test.yml`** - GitHub Actions workflow file

### Workflow Configuration

The workflow should:
- **Name**: `Run Tests`
- **Trigger on**:
  - Push to `main` branch
  - Pull requests targeting `main` branch
- **Jobs**:
  - `test`: Run Go unit tests
    - **Runs on**: `ubuntu-latest`
    - **Steps**:
      1. Checkout repository
      2. Set up Go (version 1.26.x to match go.mod)
      3. Run tests with verbose output

### Workflow File Structure

```yaml
name: Run Tests

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up Go
        uses: actions/setup-go@v5
        with:
          go-version: '1.26.x'
      - name: Run tests
        run: go test -v ./...
```

## Acceptance Criteria

- [ ] `.github/workflows/test.yml` file is created
- [ ] Workflow triggers on push to `main` branch
- [ ] Workflow triggers on pull requests to `main` branch
- [ ] Workflow uses appropriate Go version matching `go.mod` (1.26.x)
- [ ] Workflow runs all tests in the repository
- [ ] Workflow uses latest stable versions of GitHub Actions (checkout@v4, setup-go@v5)
- [ ] Workflow runs on Ubuntu latest runner
- [ ] Tests run with verbose output for better debugging

## Test Cases

### Workflow Validation Scenarios

1. **Push to main branch**
   - Workflow should automatically trigger
   - Tests should run and report pass/fail status

2. **Pull request to main branch**
   - Workflow should automatically trigger on PR creation
   - Workflow should re-run on new commits to the PR
   - Tests should run and report pass/fail status

3. **Push to feature branch (not main)**
   - Workflow should NOT trigger (only main branch and PRs)

4. **Test execution**
   - All tests in `math_test.go` should execute
   - `TestAdd` with all sub-tests should pass
   - `TestIsOdd` with all sub-tests should pass
   - `TestIsEven` with all sub-tests should pass

5. **Failure handling**
   - If any test fails, the workflow job should fail
   - GitHub should show the failure on the PR/commit
